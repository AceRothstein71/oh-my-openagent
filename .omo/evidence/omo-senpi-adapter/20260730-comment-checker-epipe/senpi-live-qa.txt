What was observed
-----------------
- The installed Senpi process returned exactly status 0, with no signal and no
  timeout, after the mock-provider write flow while the configured checker was
  `/usr/bin/false`.
- The expected file was written, proving the write-like tool-result surface was
  exercised. The immediate child exit produced no EPIPE, Unhandled, uncaught,
  or host-crash marker in either captured stream. `containsCheckingComments` is
  false because this noninteractive turn emits no spinner; it is not used as
  evidence of checker feedback. The normal driver separately proved feedback
  with `commentChecker:"PASS"`.
- The real `~/.senpi/agent` full SHA-256 directory digest was exactly unchanged
  before and after the early-exit turn. Its isolation credential-file digest was
  also exactly unchanged. Only digest values, never config contents, were read.
- The early-exit driver removed its sandbox in `finally`; its post-run process
  scan found zero references to that sandbox.

Why this is enough
------------------
This covers the real host boundary that matters for the fix: Senpi loaded the
local extension, the mock provider triggered the affected write hook, and an
actual child process exited without reading stdin. The host completed with
status 0 and no EPIPE or unhandled-error marker. The normal real-checker path
also preserved comment feedback.

The normal driver's broad real-directory digest changed while unrelated live
Senpi activity was present. It is therefore recorded as informational rather
than isolation proof. The focused immediate-exit run took its own full
real-directory digest immediately before and after the bounded run and observed
equality; that is the isolation assertion used for this scenario.
